# Changelog

User-facing changes and migration notes are recorded here, starting with the build modernization. Earlier releases are not yet catalogued in this file.

## Unreleased

### Added

- n-site Hamiltonian terms for exact diagonalization (`fulldiag`, `sparsediag`). An `<NSITE>` in a `<UNITCELL>` or `<GRAPH>` lists an ordered group of sites; an `<NSITETERM sites="i j k l">` in a `<HAMILTONIAN>` is applied to every n-site group of its type, with arbitrary operator strings, any number of sites, and fermion signs handled. Terms that leave the `CONSERVED_QUANTUMNUMBERS` sector are refused. A term that changes a quantum number capped by a cutoff parameter, such as a boson `N <= Nmax`, prints a warning that the results depend on the cutoff. Other applications refuse models that combine n-site terms with n-site groups instead of ignoring them. See [the syntax](src/alps/model/docs/nsite_terms.md).

### Fixed

- Store an empty `std::map` in an HDF5 archive as an empty group, so it reads back as an empty map instead of a missing path. Older readers load such files as empty maps too.
- Resolve HDF5 attribute paths written as `path@name` (ALPSCore's spelling) and attributes of the root group (`/@name`, or `@name` in the root context). These used to drop the character before `@` or fail; ALPS's `path/@name` spelling names the same object as before.
- Release HDF5 scalar string buffers after reads, including failed conversions, and owned observables when clearing an `ObservableSet`.
- Correct scalar/vector Monte Carlo result negation and keep uncertainties nonnegative under negative scaling or reciprocal arithmetic. Preserve empty histogram ranges, avoid invalid access during empty vector/valarray conversions, and create private temporary files on Unix independently of the caller's umask.
- Initialize the completion schedule of `alps::progress_callback` before first use.
- Read integer checkpoint parameters at their stored width and reject out-of-range conversion without changing existing values.
- Preserve `txt2archive`, `xml2archive`, and the optional SQLite `archive` program; correct malformed-input handling.
- Report MaxEnt CLI help and input errors with normal exit codes instead of continuing into an empty input or aborting on an exception. Valid scientific runs are unchanged.
- Reject unsupported native C++ parameter checkpoint datatypes with the dataset path in the diagnostic, instead of silently substituting zero. Existing supported types and custom readers retain their decoding behavior; a failed parameter reload preserves the previous values.
- Generate XML plotting scripts compatible with Python 3 through the `alps-xml` CLI.
- Correct the Heisenberg tutorial's vector dot product and allow its vector implementation to compile without x86 SIMD support.
- Remove undefined behavior in XDR callbacks and integer-range boundary checks exposed by sanitizers.
- Keep full double precision for parameter values substituted into `SITETERM`, `BONDTERM` and `NSITETERM` expressions. They were rounded to 6 significant digits, so for example `mu=0.123456789123` acted as `0.123457`. Inputs whose parameters have at most 6 significant digits are unchanged.
- Loading a `std::map` from HDF5 through an empty path inside an archive context, as a class's `load(archive&)` does, read the entries below the root instead of below the context. Entry paths are now completed against the context, as saving already did and as ALPSCore does.
- Saving a `std::map` at an HDF5 archive's root tried to delete the root group and failed. It now writes its entries beside the root's other children.
- End thermalization in the interaction-expansion solver (`interaction`, `alps::solvers::ctint`) after `THERMALIZATION` steps. It never ended, so a run with `THERMALIZATION` > 0 went on until `MAX_TIME` and measured from the first step. Such runs now discard the thermalization steps and stop `SWEEPS` steps later, so their results change; one whose `MAX_TIME` ends during thermalization stops with "No measurements available." Under MPI, a run that ends while any rank is still thermalizing stops with an error on every rank. Runs with `THERMALIZATION=0` are unchanged.
- Under MPI, `collect_results()` now throws on every rank when an observable was measured on some ranks but not others, for example when `MAX_TIME` ends while some ranks are still thermalizing. It used to skip the collective reduction only on the empty ranks, which could hang the run.

### Changed

- Consolidate native runtime tests under GoogleTest with individual CTest cases, historical numerical and serialization references, isolated temporary files, and explicit MPI/sanitizer registration. GoogleTest is a test-only dependency; builds with tests disabled do not acquire or install it.
- Keep Python tests and fixtures alongside pyalps and run standalone numerical tutorial tests independently. Retire the optional Boost.Python differential build audit after retaining application checks and focused regressions; see [the coverage assessment](tests/python-migration.md) for historical compatibility limits.

- Require HDF5 1.10.5 or newer for source builds and installed SDK consumers, retaining compatibility with the system package used by the manylinux_2_28 wheel build.
- Support Python 3.10 or newer for pyalps. Keep separate CPython 3.10 and 3.11 wheels and use one `cp312-abi3` wheel for Python 3.12 and newer. Downstream nanobind extensions must pass `STABLE_ABI` to share pyalps types on Python 3.12+.
- Add `mpi`, `openmp`, and `mpi-openmp` configure/build/test presets with separate build and install directories. The default build keeps MPI and OpenMP disabled.
- Export `ALPS::configuration`, `ALPS::containers`, `ALPS::numerics`, `ALPS::numeric_io` and `ALPS::solver_headers` as interface targets with their own header sets and dependencies. Separate container storage, numerical algorithms and HDF5 adapters; foundations no longer inherit aggregate `ALPS::headers`. Numerical algorithms and public include names are preserved.
- Organize `src/alps/` by responsibility, with module-local headers, sources and tests. Configuration templates live in `cmake/config/`, and generated headers use `<build-dir>/generated/include/alps/`. Explicit header file sets preserve public include names. See the [module layout](src/alps/README.md).
- Export independently linkable runtime components `ALPS::utilities`, `ALPS::hdf5`, `ALPS::params`, `ALPS::osiris`, `ALPS::xml` and `ALPS::cli`. `ALPS::alps` links them transitively; Python packages carry one copy of each component. Params text/XML and older `Parameters` conversion adapters remain in `ALPS::alps`, with unchanged public header names. Archive formats and existing parsing behavior are preserved. Rebuild downstream binaries after the library splits.
- MaxEnt's solver and executable link the foundation components without `ALPS::alps`. The executable uses `ALPS::cli` and reads typed params directly from HDF5. Scientific calculations and stop-callback behavior are preserved.
- Group `src/tools/` commands by responsibility. Keep historical inactive sources without enabling them; executable names and installation components are preserved. `pconfig` now links only utilities.
- Require CMake 3.27 or newer and an externally installed Boost 1.76 or newer with CMake packages. The SDK requires C++17/C11 compilers, HDF5's C library, and LP64 BLAS/LAPACK; bundled Boost builds and alternate numerical integer/symbol ABIs are no longer supported.
- Export CMake targets for the installed SDK, applications and solver libraries. Downstream C++ projects link `ALPS::alps`; Python extensions sharing pyalps objects use `pyalps::runtime`. MaxEnt, CT-HYB and CT-INT Python wrappers link the SDK's solver libraries instead of compiling their implementations again.
- Make MPI opt-in with `ALPS_ENABLE_MPI=ON`. Standalone builds enable applications and native tests by default; embedded `add_subdirectory` builds default to the library alone. The default SDK uses shared libraries, as required by the Python bindings.
- Top-level single-configuration builds still default to `CMAKE_BUILD_TYPE=Release`; embedded builds leave the build type to the parent project.
- Support editable Python development against an installed SDK, with packaged native runtime resources and explicit downstream ABI checks. Redistributable wheels bundle native dependencies through platform repair and are tested after installation on fresh runners.
- Build the C++ and Fortran examples in `tutorials/examples/` as standalone projects against an installed SDK. Tutorial sources are installed only when the `tutorials` component is requested.

The old spellings and names remain, deprecated, while `ALPS_LEGACY_API` is on (the default); see [the legacy layer](legacy/README.md). Rebuild downstream binaries.

Its remaining shared helpers move to `<alps/utilities/...>`; `numeric_cast.hpp` moves to `<alps/numeric/numeric_cast.hpp>` and `cli.hpp` to `<alps/cli.hpp>`. `assign.hpp` and `set_zero.hpp` keep their spelling and now belong to the ALEA headers that use them. The integer-property constructor likewise rejects bits other than `READ`, `WRITE`, `REPLACE`, `COMPRESS`, `LARGE` and `MEMORY`.

Copy assignment is deleted: it shared the file without counting the reference, so closing either archive could close the other's file. Copy construction is unchanged.

It keeps ALPSCore's include spellings and namespace (`<alps/alea.hpp>`, `<alps/alea/*.hpp>`, `alps::alea`). It requires Eigen 3.3 or newer and is built only when Eigen is found; installed SDK consumers request it with `find_package(ALPS COMPONENTS aleav2)`. In MPI builds it includes ALPSCore's `alps::alea::mpi_reducer`. ALPS's own ALEA (`<alps/alea.h>`) remains the default: it is unchanged and not deprecated, and both can be used in the same program. Nothing in ALPS uses ALEA v2 yet; the two will be swapped only after a conformance suite passes on both. See [its README](src/alps/aleav2/README.md) for provenance and license.

Like `ALPS::aleav2`, it requires Eigen 3.3 or newer, is built only when Eigen is found, and is requested with `find_package(ALPS COMPONENTS gf)`. In MPI builds, its broadcasts use ALPSCore's `<alps/utilities/mpi.hpp>` from `ALPS::utilities`. `alps::hdf5::wrong_dimensions` is added from ALPSCore. See [its README](src/alps/gf/README.md) for provenance and license.
- Adopt ALPSCore's `<alps/numeric/vector_functions.hpp>` and add its `<alps/numeric/inf.hpp>`. Vector arithmetic in `alps::numeric` now treats a default-constructed vector as the zero vector, and `+=`, `-=`, `*=` and `/=` throw `std::runtime_error` on a size mismatch. Scaling by a scalar of another arithmetic type, unary `+` and `operator<<` keep working. The functors of `<alps/numeric/functional.hpp>` now come from `vector_functions.hpp`. Code that declares both `boost::numeric::operators::operator*` and `alps::numeric::operator*` (or `+`, `-`, `/`) in one scope must drop the Boost declaration. See [the numerics README](src/alps/numerics/README.md).
- Add `ALPS::accumulators`, the accumulators library of the ALPS Core Libraries, copied from ALPSCore with its tests (`alps::accumulators`, `<alps/accumulators.hpp>`, `<alps/accumulators/*.hpp>`). It is always built, is part of `ALPS::alps`, and installed SDK consumers can request it with `find_package(ALPS COMPONENTS accumulators)`. `<alps/config.hpp>`, ALPSCore's name for the configuration header, now ships alongside `<alps/config.h>`, and ALPSCore's `<alps/numeric/{check_size,scalar,rectangularize,boost_array_functions}.hpp>` and, in MPI builds, `<alps/utilities/boost_mpi.hpp>` are added. See [its README](src/alps/accumulators/README.md) for provenance and license.
- Add ALPSCore's parameters to `ALPS::params`, copied from ALPSCore with their tests: `alps::params_ns::params` and `alps::params_ns::dictionary` in `<alps/params.hpp>`, `<alps/dictionary.hpp>` and `<alps/params/*.hpp>`, with the iniparser library they read INI files with. Like the NGS `alps::params` of `<alps/ngs/params.hpp>`, which is unchanged, ALPSCore's header names its class `alps::params`, so one translation unit can include only one of the two headers. See [its README](src/alps/params/README.md) for provenance and licenses.
- `pyalps.loadBinningAnalysis` reads the binning analysis of results written by ALPSCore's accumulators (`error_bins`), as well as ALEA's `timeseries/logbinning` data. `pyalps.loadMeasurements` already read their means, errors and counts, and their parameters. A frozen file written by ALPSCore checks both. The returned `hdf5_path` now includes the `/` before the observable name.
- The hybridization solver (`hybridization`, `pyalps.cthyb`) gathers its parameter defaults in `hybridization::define_parameters`, so the `/parameters` it writes now list the defaults it used. A measurement that needs `N_MATSUBARA`, `N_LEGENDRE`, `N_nn`, `N_W` or `N_w2` now rejects the value 0 as well as a missing value, and an empty `U_MATRIX`, `MU_VECTOR` or `RET_INT_K` counts as unset.
- The interaction-expansion solver (`interaction`, `pyalps.ctint`) gathers its parameter defaults in `InteractionExpansion::define_parameters`, and its simulation and evaluation read the sizes with older spellings or computed defaults (`N_MATSUBARA` or `NMATSUBARA`, `N_TAU` or `N`, `FLAVORS` or `N_ORBITALS`, `NSELF`, `NMATSUBARA_MEASUREMENTS`, `MEASUREMENT_PERIOD`, `CONVERGENCE_CHECK_PERIOD`) through one set of functions. `ATOMIC` and `TAU_DISCRETIZATION_FOR_EXP` now act by value: `ATOMIC=0` no longer selects the atomic limit, and `TAU_DISCRETIZATION_FOR_EXP=0` computes the exponentials on the fly.
- MaxEnt gathers its parameter defaults in `MaxEntSimulation::define_parameters`. An empty `DATA` or `COVARIANCE_MATRIX` counts as unset.
- Replace the NGS parameters with ALPSCore's. `alps::params` is ALPSCore's `alps::params_ns::params` from `<alps/params.hpp>` in every ALPS program, solver and pyalps; `<alps/ngs/params.hpp>` and its `detail` headers are removed. A program defines each parameter with `define<T>()`, with a default where one applies, and reads it with `as<T>()` or a conversion. Parameter files, XML job files, HDF5 groups and Python dicts supply text, which `define<T>()` parses with the declared type. A missing parameter, or a value that does not parse, is an error naming the parameter. This includes a non-integral or malformed number for an integer parameter. Reading an undefined parameter throws. The solvers and MaxEnt print the parameters they were given but never read on standard error. See [the params README](src/alps/params/README.md).
- `alps::mcbase::define_parameters()` defines `SEED` (default 42), and `alps::mcmpiadapter` adds `Tmin` and `Tmax` (defaults 1 and 600). The hybridization and interaction-expansion solvers, MaxEnt, pyalps's `mcbase` and the exported simulations call their simulation's `define_parameters()` before constructing it.
- `alps::make_parameters_from_xml` and the new `alps::make_parameters_from_file` (`<alps/ngs/make_parameters_from_file.hpp>`, for ALPS parameter files) return ALPSCore's parameters. `alps::make_deprecated_parameters` passes every supplied parameter to `alps::Parameters` as the supplied text. The NGS version printed numbers with six significant digits, so solvers that hand parameters to the lattice and model libraries now see their full precision.
- `/parameters` keeps a dataset for every parameter, including those supplied but never defined. ALPSCore's parameters add their attributes to the group. Groups without them, as pyalps, `alps::Parameters` and the NGS parameters wrote them, load as supplied text.
- `pyalps.ngs.params` wraps ALPSCore's parameters and stores a copy of each Python value as text. It keeps no reference to the Python object. Booleans become `1` and `0`. `None`, complex numbers, multidimensional arrays, nested sequences and dicts, and list elements containing a comma are a `TypeError` naming the parameter. A parameter only supplied, and not yet defined by a program, reads back from its text: `"42"` as `42`, `2.0` as `2`, `[5]` as `5`, numeric lists as NumPy arrays and `[True, False]` as `array([1, 0])`. Keys iterate in sorted order, and `del parameters[key]` drops every definition.
- A checkpoint written by an NGS build cannot be resumed: its parameters load as supplied text, without the definitions the simulation reads them with. Finish runs before upgrading; result files stay readable.
- Replace the NGS Monte Carlo simulation base with ALPSCore's, `ALPS::mc`, copied from ALPSCore with its tests: `alps::mcbase`, `alps::mcmpiadapter`, `alps::check_schedule`, `alps::stop_callback`, `alps::random01` and the functions of `<alps/mc/api.hpp>`, in `<alps/mc/*.hpp>`. `ALPS::alps` links it, and installed SDK consumers can request it with `find_package(ALPS COMPONENTS mc)`. The NGS headers `<alps/mcbase.hpp>`, `<alps/mcmpiadapter.hpp>`, `<alps/check_schedule.hpp>`, `<alps/stop_callback.hpp>`, `<alps/ngs.hpp>`, `<alps/ngs/api.hpp>` and `<alps/ngs/random01.hpp>` are removed; `<alps/progress_callback.hpp>` remains. See [its README](src/alps/mc/README.md) for provenance. For simulations:
  - Observables are ALPSCore's accumulators: `measurements` is an `alps::accumulators::accumulator_set`, and `collect_results()` returns an `alps::accumulators::result_set`. Results with binning store `tau` where ALEA stored `tau/value`, add `error_bins`, and store no `variance`.
  - `mcbase` has no `params` member; read `parameters`. `random` is no longer `mutable`, so `const` member functions cannot draw from it. `save(filename)` and `load(filename)` take a `std::string`, and the generator's state is stored at `checkpoint/engine`. `load` rejects a checkpoint written by the NGS `mcbase`, which cannot be resumed.
  - `mcmpiadapter` takes an `alps::mpi::communicator`. Constructed without a schedule, it checks the completed fraction between `Tmin` and `Tmax` seconds (defaults 1 and 600); the NGS adapter checked between 60 and 900 seconds. `alps::check_schedule(tmin, tmax)` has no default arguments and no `check_interval()`, and it measures whole seconds. Its seed for rank `r` is still `SEED + r`. `BINNUMBER`, the number of bins the NGS adapter kept when it merged ALEA results across ranks, has no counterpart, because ALPSCore's accumulators merge their own bins. An input that sets it still runs; the hybridization and interaction-expansion solvers list it among the parameters they never read.
  - `collect_results()` on the MPI adapter leaves out observables that no rank measured, and throws if only some ranks measured one. The NGS adapter returned them without measurements.
- The hybridization and interaction-expansion solvers measure with ALPSCore's accumulators. Their results are statistically equal to the NGS solvers': means are identical, errors and autocorrelation times come from ALPSCore's binning analysis, and the hybridization solver computes covariances by jackknife from the bins, as ALEA did. The interaction-expansion solver measures the `Sz` correlations (`Sz_i`, `Sz2_i`, `Sz0_Szi`) as the value times the sign and saves their results divided by `Sign`, as the NGS signed observables stored them: the jackknife estimate, over whole bins, of the mean of the value times the sign over the mean sign, with its jackknife error. Their `count` is the number of measurements in whole bins, which the jackknife uses. They also store their jackknife bins (`jacknife`), the `tau` of the value times the sign, and `error_bins` propagated from it and from `Sign`, which do not end at `mean/error`. Its three timer observables, which it never measured, are no longer in its results.
- `pyalps.ngs` observables and results wrap ALPSCore's accumulators and results. `createRealObservable` and `createRealVectorObservable` create full-binning accumulators, with 128 bins for a bin number of 0, as before. Results lose `variance`; `bins` is available for scalar results; and `print()` shows ALPSCore's summary. A result negated, or shifted or scaled by a constant, keeps its mean and error, shifted or scaled. The count, mean and error of a result transformed by a function or combined with another come from the jackknife over whole bins, which leaves out the samples of the last, incomplete bin, so the mean can differ from the transformed mean within its error. `merge()` raises `RuntimeError` for full-binning observables, which ALPSCore cannot merge, and `observables.reset()` ignores its argument. A name containing `/` is saved as nested groups and does not load back. Assigning a result without measurements to `results[name]` raises `ValueError`. Appending a sample that does not fit an observable, such as a vector of another size, raises `ValueError`.
- Retire the NGS accumulators (`alps::accumulator`, `<alps/ngs/accumulator.hpp>`, `<alps/ngs/accumulator/*.hpp>` and `<alps/ngs/mpi.hpp>`), the NGS observables over ALEA (`alps::mcobservables`, `alps::mcresults`, `<alps/ngs/mcobservable.hpp>`, `<alps/ngs/mcobservables.hpp>`, `<alps/ngs/mcresult.hpp>`, `<alps/ngs/mcresults.hpp>` and `<alps/ngs/observablewrappers.hpp>`), the CMake option `ALPS_NGS_USE_NEW_ALEA` and the Python module `pyalps.pyngsaccumulator_c`. ALPSCore's accumulators replace them. `<alps/ngs/result.hpp>`, which included headers that do not exist, and the unbuilt accumulator prototypes in `tutorials/examples/ngs/` are removed as well. ALEA (`<alps/alea.h>`, `pyalps.alea`) is unchanged.

### Migration

This release retires the NGS layer without a deprecation period, as an exception to the rule that a removed spelling first spends a release as a deprecated forwarder under `legacy/`. The NGS parameters, Monte Carlo base, observables and accumulators were an unfinished generation of the library, used in ALPS only by the hybridization and interaction-expansion solvers, MaxEnt, pyalps and the NGS tutorials, which all move with them. ALPSCore's modules, which grew out of that layer, replace them under the same class names (`alps::params`, `alps::mcbase`), so no forwarding header could serve both at once. The retirements come in steps: the parameters first, with the unused parapack and scheduler bridges on them, then the Monte Carlo base, then the observables and accumulators. Each removed interface has a row in the table below, and `tests/cmake/preserved_public_headers.json` lists every retired header with the reason.

Public and vendored headers are retained, except those that the table below lists as removed. Tutorial consumers use the exported SDK targets. The ALPS 2.x consumer interfaces `UseALPS.cmake`, `UsePyALPS.cmake` and `include.mk` remain installed as deprecated compatibility layers over those targets. Configure downstream projects using [CONTRIBUTING.md](CONTRIBUTING.md#getting-started-with-the-code).

Installing over an existing prefix leaves the removed headers in place. A program that includes one of them beside its replacement then fails to compile, for example with a redefinition of `alps::mcbase`. Install into a new prefix, or delete the headers that `tests/cmake/preserved_public_headers.json` lists under `retired`.

Numerical matrix/vector persistence now requires an explicit adapter: include `<alps/hdf5/matrix.hpp>` or `<alps/hdf5/numeric_vector.hpp>` and link `ALPS::numeric_io`. The matrix umbrella `<alps/numeric/matrix.hpp>` no longer includes HDF5 automatically. Diagonal matrices and deprecated BLAS matrix/vector classes retain their archive `save`/`load` members without requiring HDF5 headers in the numerical interfaces. Numerical matrix `write_xml` and XML insertion remain available through `<alps/xml/matrix.hpp>` and `ALPS::numeric_xml`. Header ownership moves preserve public include spellings; consumers of persistence and XML output must include the corresponding adapters.
